## Правила лабов и UI (применять ВСЕГДА, без напоминаний)

Песочницы — папки `lab-*/` (демо-страницы, noindex, не на боевом). Эржан в них подбирает дизайн, потом выбранное переносим в боевой. См. память `project_sandboxes`, `feedback_glass_standard`.

### Два вида настроек — не путать, всегда разделять
1. **Дизайн-полоса лаба** — ВСЕГДА сверху, горизонтальная сворачиваемая полоса (механизм `*-min`, кнопка «Свернуть настройки»). Это для нас (подбор дизайна): варианты раскладок/эффектов/видов. На боевой НЕ переносится — переносим только выбранный вариант, остальное выкидываем/фиксируем в дефолт.
2. **⚙ Настройки юзера** — ВНУТРИ контента, под кнопкой-шестерёнкой ⚙, попап в стекле. Это для реального посетителя: шрифт, плотность, размер, сила стекла и т.п. На боевом живут в ⚙.
   Правило: пока подбираем — всё в верхней полосе; финалим вариант → решаем какие 2-3 параметра станут пользовательскими (в ⚙), остальное = фиксированный дефолт.

### ★ ЗАКОН СТЕКЛА — МЕХАНИЗМ (читать ПЕРЕД любым видимым блоком)
Закон вшит в код, а не «в голову». Не обходить, не изобретать заново.
- **Любой видимый блок (панель/модалка/попап/полоса настроек) = носит класс `glass`.** Этого достаточно: стекло появится само и будет слушаться ⚙ юзера (сила/оттенок/насыщенность). Источник правды — переменные `--glass-*` в `styles.css` (блок `html[data-glass="on"]`, ~стр. 7451).
- **ЗАПРЕЩЕНО писать своё стекло руками** (свой `background`/`backdrop-filter`/`border`/`border-radius` для эффекта стекла). Это создаёт дубль и расхождение — корень всех болезней (`feedback_design_system`). Только `class="glass"` + переменные.
- Старый список имён в `:is(.lvl-container, .m-win, .hub-card …)` = легаси-блоки, подключённые поимённо до появления `.glass`. **Новое — только через `.glass`**, в список ничего не дописывать.
- Нужны уникальные числа (другой радиус, другой тинт под конкретный блок) — менять ПЕРЕМЕННУЮ у этого блока, а не переопределять весь эффект.
- **★ ЕДИНОЕ СТЕКЛО — одни ЧИСЛА на весь сайт (не только класс).** Одна сила blur (`--glass-blur`) и один backdrop за модалками — общие для ВСЕГО. Ни один блок не пишет свой `blur(Npx)` или своё затемнение фона. Ни один видимый блок не исключение: шапка таблицы, главные вкладки Статс/WinRate, панель уровня = тоже стекло, без захардкоженного синего. *Почему:* даже с `class="glass"` блоки расходятся, если у каждого свои числа → «рельс мутит сильно, шапка синяя, вкладки без стекла». Один материал = одна правда, меняешь глобально → меняется везде разом.

### ★ ЗАКОН МАТРЁШКИ — вложенные модалки (читать ПЕРЕД любой модалкой)
Механизм УЖЕ есть в коде — не изобретать. Любая модалка открывается/закрывается ТОЛЬКО через `openModal(id)`/`closeModal(id)` (`app.js`, блок «MODAL SYSTEM — unified stack + history», ~стр. 41). Стопка `_modalStack`, кнопка «Назад» (popstate) и Esc закрывают ТОЛЬКО верхнюю.
- **Чтобы новая модалка работала правильно — ЗАРЕГИСТРИРУЙ её id:** в `MODAL_IDS` (все модалки) и, если она открывается ПОВЕРХ родителя (родитель остаётся видим), ещё и в `OVERLAY_MODALS`. Открой через `openModal('myMask')`, закрой через `closeModal('myMask')`.
- Открыл A → из неё B → закрыл B → остаёшься в A (а НЕ пустота и НЕ «закрылось всё»). Это частый баг при переносе — модалка открывается своим `classList.add('active')` МИМО стопки. ЗАПРЕЩЕНО: свой хардкод открытия/закрытия и «закрыть всё».
- «Клетка» (активный кооп-драфт): выхода нет вообще — повесь на модалку атрибут `data-no-esc` (Esc её не закроет), см. `feedback_top_tabs_contract` (инлайн/клетка).
- **★ ЕДИНОЕ ОТКРЫТИЕ/ЗАКРЫТИЕ.** Все модалки/попапы открываются и закрываются ОДИНАКОВО — один переход (или резко), своей анимации у отдельной модалки НЕТ. При ПЕРЕКЛЮЧЕНИИ A→B фон НЕ мелькает (прямая замена, без вспышки фона на миллисекунду). *Почему:* разнобой переходов + мелькание фона = дёрганье и «некрасиво». См. `feedback_no_flash`.
- **★ ИНСТРУМЕНТ САЙДБАРА = ВКЛАДКА, не модалка.** У инструментов сайдбара НЕТ модальной рамки/маски/затемнения — это инлайн-контент справа, рельс остаётся, меняется только контент. Модальная рамка тут = легаси и источник багов переключения. См. `feedback_top_tabs_contract`.
  - **ГРАНИЦА (исключение):** драфтер и КООП/СЕРИИ-драфт — НЕ инлайн-вкладки. Они ВСЕГДА фуллскрин. Кооп-драфт = «клетка»: когда драфт начался, выхода НЕТ вообще (`data-no-esc`). Это исключение не трогать при переводе остальных инструментов в инлайн.

### Стекло + фон (стандарт сайта)
- **Любая модалка/окно = стекло** (матовое полупрозрачное + `backdrop-filter: blur`). Без исключений.
- **Стекло размывает то, что ЗА ним** — значит за стеклом ВСЕГДА должно лежать что размывать. Пустая тёмная панель = баг (стекла не видно).
- **За стеклом — ОДИН сплэш-арт на весь сайт**, выбранный глобально (одна картинка на ВСЕ модалки), а НЕ свой арт у каждой модалки. Арт — это сплэш чемпа (напр. Brand), НЕ градиент. (Разные арты по чемпам = временные заглушки для проверки механизма.)
- **Цветовой ореол/фон не должен меняться рывком** при переходе между окнами одного потока (карточка → сравнение → пикер). Первый кадр сразу правильный (см. `feedback_no_flash`).

### Скроллы (см. `feedback_no_ugly_scrollbar`, `feedback_no_layout_jerk`)
- Никогда не оставлять жирный дефолтный ползунок. Контент вписывать (flex), скролл — тонкий/стилизованный.
- Фуллскрин-модалки — без скролла страницы.
- Переключатели/фильтры НЕ меняют размер/положение блока (фикс. габариты + внутренний скролл).

После правок файлов лаба ВСЕГДА бампить `?v=N` на `<link>`/`<script>` в его `index.html` — Эржан открывает локальные файлы и часто не делает Ctrl+F5.

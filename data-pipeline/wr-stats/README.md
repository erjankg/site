# Архив снимков винрейтов

Здесь лежит **история** статы Wild Rift: по файлу на день, имя = `ГГГГММДД.json`.

Зачем: `data-pipeline/wr-stats.json` каждый прогон **перезаписывается**, вчерашних чисел не остаётся.
Без истории спарклайны («как менялся WR чемпа») и tier-movers («кто вырос за неделю») можно только
нарисовать демо-цифрами. Архив = настоящие данные для них.

## Кто что делает

| Файл | Роль |
|---|---|
| `snapshot.mjs` | Формат снимка. Описан **в одном месте**, пишут через него все. |
| `ГГГГММДД.json` | Сам снимок дня. Пишет `../fetch-wr-stats.mjs` в конце каждого прогона. |
| `history.mjs` | Чтение архива + **дельта двух снимков**. Ничего не пишет. |
| `backfill.mjs` | Разовая штука: сделать снимок из старой копии `wr-stats.json` (в т.ч. из истории git). |

`../wr-stats.json` (боевой, его читают калькулятор, метахаб, `build-calc-data.mjs`) **не менялся ни на байт
по структуре** — те же поля, тот же порядок. Архив живёт рядом и никем, кроме `history.mjs`, не читается.

## Формат снимка

```jsonc
{
  "format": 1,
  "snapshotDate": "20260726",     // дата данных Tencent (dtstatdate), она же имя файла
  "sourceDate": "20260726",       // что именно отдал источник (null если пришлось взять сегодняшнюю дату)
  "fetchedAt": "2026-07-26T…",    // когда стянули (null у бэкфилла — там дата неизвестна)
  "count": 871,
  "ranks":  { "0": "diamond_plus", "1": "master_plus", "2": "challenger", "3": "apex", "4": "all" },
  "names":  { "10004": { "ru": "Амуму", "en": "Amumu", "cn": "阿木木" } },
  "rows":   [ { "heroId": "10004", "rankSlice": "2", "role": "Jungle", "tier": "S", "wr": 56.6, "pr": 4.2, "br": 0.2 } ]
}
```

Снимок **урезанный**: имена вынесены в общий словарь `names`, из строки убраны `name/nameEN/nameCN/rank/date/wrTrend`
(всё восстановимо). Полная копия боевого файла весила бы 275 КБ в день, урезанная — ~90 КБ (~13 КБ после gzip,
а git хранит сжатые дельты похожих файлов, так что реальный рост репозитория меньше). Строки пишутся
**по одной на линию** — чтобы `git diff` архива читался глазами.

Ключ строки уникален тройкой `heroId + rankSlice + role`.

## Команды

```bash
node data-pipeline/wr-stats/history.mjs list                       # что есть в архиве
node data-pipeline/wr-stats/history.mjs diff   [from] [to]         # кто вырос/упал (по умолчанию prev → latest)
node data-pipeline/wr-stats/history.mjs movers [from] [to]         # tier-movers: смена тира + рост/падение WR
node data-pipeline/wr-stats/history.mjs trend  Джакс --days 14     # ряд для спарклайна
```

Флаги: `--rank diamond_plus|master_plus|challenger|apex|all` (по умолчанию `diamond_plus`), `--role Jungle`,
`--limit N`, `--min-pr 0.5` (отсечь строки с копеечным пикрейтом), `--days N`.

Ссылка на снимок везде одна и та же: `20260726` · `latest` · `prev` · `-3` (на 3 шага назад) · `live`
(текущий `wr-stats.json`). Пока архив пуст, `latest` сам падает на `live` — код не ломается в первый день.

## Как использовать из кода

```js
import { diffSnapshots, tierMovers, championTrend } from './data-pipeline/wr-stats/history.mjs';

const movers = tierMovers('prev', 'latest', { rank: 'diamond_plus', minPr: 0.5, limit: 10 });
// → { wrRisers, wrFallers, tierUp, tierDown, newcomers }

const line = championTrend('Джакс', { rank: 'diamond_plus', days: 14 });
// → { name, role, points: [{ date, wr, pr, br, tier }], dWr }
```

`diffSnapshots` помечает строки: `ok` (есть в обоих днях), `new` (чемпион/роль появились), `gone` (пропали) —
чтобы новичок в списке не выглядел как «вырос с нуля».

## Грабли, на которые уже наступили

- **Старые файлы собраны другой картой линий.** До 2026-06 позиции Tencent раскладывались как
  `{1:Baron, 2:Mid, 3:Jungle, 4:Support, 5:Dragon}`, сейчас `{1:Mid, 2:Baron, 3:Dragon, 4:Support, 5:Jungle}`.
  В снимке от 20260609 Амуму был «Dragon». `backfill.mjs` ловит такие файлы по контрольным чемпионам
  (Амуму=лес, Гарен=топ, Каиса=адк, Ари=мид) и чинит роли сам, сообщая об этом. Отключить: `--no-remap`.
- **Тренд без бракета — каша.** `championTrend` требует конкретный `rank`: иначе в один ряд попадут
  5 разных выборок.
- **Роль в ряду фиксируется один раз** (по свежему снимку), иначе линия прыгает Baron↔Dragon и сравнивает
  разные линии.
- **Дни без данных пропускаются**, а не рисуются нулями — провал до 0% на спарклайне был бы враньём.

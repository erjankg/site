# 🤖 Сбор данных Wild Rift (data-pipeline)

Два робота тянут свежую стату **автоматически** — больше не нужно копировать руками.

## Что внутри

| Файл | Что делает | Источник |
|------|-----------|----------|
| `fetch-wr-stats.mjs` | WR / пикрейт / банрейт / тир **всех чемпионов** | Tencent CN (`mlol.qt.qq.com`) напрямую |
| `fetch-base-stats.mjs` | **Базовые статы** всех чемпионов: AD/HP/мана/броня/MR (+рост), скорость передвижения, реген, роли, ресурс; дальность и скорость атаки | Tencent (`game.gtimg.cn/.../js/hero/<id>.js`) + Riot Data Dragon (дальность/AS) |
| `fetch-guide.mjs` | Гайд по **одному** чемпиону: матчапы, сборки, руны, заклинания, прокачка, контры | wildriftallstats.ru |
| `fetch-all.mjs` | То же, но по **всем 138** чемпионам сразу | wildriftallstats.ru |
| `build-champion-tags.mjs` | **Теги механик** чемпионов (уклонение от автоатак, %HP-урон, антихил…) + 6 функций состава для ИИ-судьи. Каждый тег с цитатой умения | локально: `abilities.json` + `base-stats.json` + `champion-qualities.json` |
| `fetch-counters.mjs` | **Пары «кто кого контрит»** по линиям, с датой источника. Winrate-проценты НЕ забирает | wildriftcounter.com (осн.) + wildriftfire.com (сверка) |
| `build-matchups.mjs` | **Сшивка 3 слоёв**: статистика (winrate) → редакционные пары → «почему» из тегов | локально: `guides/*.json` + `counters.json` + `champion-tags.json` |

## Что получается (результат)

- `wr-stats.json` — список всех чемпионов с винрейтом/тиром.
- `base-stats.json` — базовые статы всех чемпионов (заменяет ручную Google-таблицу; сайт читает его первым, таблица — запасной источник).
- `guides/<чемпион>.json` — полный гайд по каждому (138 файлов).
- `guides/_index.json` — оглавление (имя, роль, тир).
- `champion-tags.json` — теги механик всех 139 + `funcs` (6 функций состава). У каждого тега `src` — цитата умения.
- `counters.json` — сырые пары со скрейпа, по линиям, с `sourceDate` и ссылкой на источник.
- `matchups.json` — **оглавление** сшивки: правила «почему», расшифровка рангов, счётчики. ~25 КБ.
- `matchups/<slug>.json` — матчапы одного чемпиона (~9–17 КБ). Страница грузит только своего, а не всё разом.

### ⚠️ Про матчапы — читать перед показом на сайте

Матчап собран из **3 слоёв**, приоритет сверху вниз:

| Слой | Что даёт | Winrate | Поле |
|---|---|---|---|
| 1. Статистика — трекер **wildriftallstats** | реальный winrate/pickrate по 4 рангам и линиям | **показываем** (источник назван и датирован) | `stat` |
| 2. Редакционные — скрейп wildriftcounter/fire | заполняют пробелы там, где статистики нет | **никогда** (источник чисел не указан) | `ed` |
| 3. «Почему» — теги умений | объяснение поверх пары, с цитатой умения | — | `why` |

- **Числа берём ТОЛЬКО из `stat`.** Если у пары есть только `ed` — она показывается без процента.
- **`stat.weak: true`** — винрейт равен простой дроби (33.3 = 1/3, 66.7 = 2/3), то есть выборка в несколько игр.
  Замерено: у ранга «Супер-сервер» таких 7.5%, у «Алмаз+» — 0.1%, поэтому заголовочное число берётся
  с самого населённого ранга. Такое число **не подавать как факт**.
- **Дату показывать ВСЕГДА**, она у каждой пары своя: статистика — апрель 2026, редакционные разъезжаются
  от апреля 2025 до июля 2026. Формат: «данные от <дата> · <источник>».
- «Почему» **не выдумывается**: не сработало правило — `why` пустой, пара показывается голой.

### 📋 КОНТРАКТ ДЛЯ UI — обязателен к исполнению

Это не пожелания, а правила показа. Данные собраны так, что нарушить их = соврать игроку.

**1. Вердикт всегда берётся по статистике.**
Есть `stat` → «контрит / контрится» считается по `stat.wr` относительно 50%. Поле `ed.verdict`
на вердикт **не влияет** — оно только для флага расхождения. Нет `stat` → вердикт из `ed.verdict`.

**2. `disagree: true` — флаг обязан быть ВИДЕН (577 пар).**
Статистика и редакция разошлись. Показываем вердикт **по статистике**, но рядом ставим пометку
вроде «источники расходятся» с возможностью посмотреть, что говорит второй. Молча прятать
расхождение нельзя: это ровно те матчапы, где интуиция сайтов спорит с реальными играми.

**3. `stat.weak: true` — числом НЕ показывать (79 пар).**
Винрейт равен простой дроби (33.3 = 1/3, 66.7 = 2/3) → за ним несколько игр. Варианты:
скрыть пару целиком, либо показать её **без процента** с подписью «мало данных».
Написать «66.7%» рядом с честными числами — значит выдать шум за факт.

**4. Дата и источник — всегда рядом с числом.**
Формат: «данные от `stat.date` · wildriftallstats» для статистики, «данные от `ed.date` ·
`ed.s`» для редакционных. Даты разъезжаются от апреля 2025 до июля 2026 — без даты число врёт.

**5. Число — только из `stat`.** У `ed` процентов нет и не будет. Если у пары один лишь `ed` —
показываем пару без процента, а не подставляем что-то похожее.

**6. Пустой `why` — это нормальный результат.** Показываем пару без объяснения. Ничего не
досочинять и не подставлять «общие слова».

**Где брать подписи:** русское имя оппонента и цитату умения — в `champion-tags.json`
(`champions[opponent].ru`, `champions[победитель].src[rules[n].tag]`); тексты правил и
расшифровку рангов — в `matchups.json` (`rules[]`, `ranks`). В `matchups/<slug>.json`
они намеренно не дублируются, чтобы файл оставался ~9 КБ.

## Как запустить вручную

```bash
node data-pipeline/fetch-wr-stats.mjs      # винрейты всех чемпионов
node data-pipeline/fetch-base-stats.mjs    # базовые статы всех чемпионов
node data-pipeline/fetch-guide.mjs aatrox  # гайд одного чемпиона (для проверки)
node data-pipeline/fetch-all.mjs           # гайды всех 138
node data-pipeline/fetch-all.mjs 5         # только первые 5 (быстрая проверка)

# матчапы — порядок важен: статистика → теги → пары → сшивка
node data-pipeline/fetch-all.mjs           # слой 1: статистика (winrate) в guides/*.json
node data-pipeline/build-champion-tags.mjs # слой 3: теги механик (локально, мгновенно)
node data-pipeline/fetch-counters.mjs      # слой 2: редакционные пары, все 139 (~6 минут)
node data-pipeline/fetch-counters.mjs jax  # дозаписать одного, остальных не трогая
node data-pipeline/build-matchups.mjs      # сшить все три слоя
```

## Автообновление (раз в день, бесплатно)

Файл `.github/workflows/update-data.yml` запускает обоих роботов **каждый день в 03:23 UTC**
прямо на серверах GitHub и коммитит свежие данные в репозиторий. Ничего на твоём компьютере
запускать не надо. Можно нажать **Run workflow** на GitHub, чтобы обновить вручную в любой момент.

## Важно

- **Имена чемпионов** в `wr-stats.json` переведены на русский (словарь `RU` внутри `fetch-wr-stats.mjs`,
  дополняй при выходе новых). Имена предметов/рун пока английские — при желании добавим словарь.
- **Источник данных** — китайский сервер Tencent (через себя и через wildriftallstats). На сайте
  держим подпись «Источник: lolm.qq.com, фан-проект» (легально-серая зона, так делают все).
- **Матчапы** обновляются у источника не каждый день (смотри поле `dataDate` в гайде).
